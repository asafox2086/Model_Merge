# my_merge 工作介绍

## 1. 工作目标

本工作围绕 `my_merge` 设计一种面向医学图像场景的事后模型融合方法。问题设定如下：多个医学机构已经在本地训练得到同构模型，服务端需要在训练结束后一次性融合这些模型，得到一个全局模型。该过程不采用联邦学习式的多轮通信，也不要求客户端在融合阶段继续训练。

方法设计必须满足三个边界条件：

1. `my_merge` 只针对医学图像任务，不作为通用 NLP 或通用自然图像模型融合算法提出。
2. 融合是一次性的 post-hoc model merging。客户端本地训练完成后，只上传 checkpoint 和允许上传的类别级统计；服务端完成一次融合后输出模型。
3. 服务端不读取客户端原始图像，不接收逐样本特征、逐样本 logit 或逐样本预测。

因此，本工作的核心不是在服务端寻找一个更复杂的候选池，也不是用公开验证集或客户端回传结果选择融合模型，而是设计一种能解释医学图像融合失败现象、同时符合隐私边界的确定性融合规则。

## 2. 现象观察

前期实验发现，常见权重空间融合方法在医学图像任务上经常出现预测坍缩。这里的坍缩不是指所有类别准确率均匀下降，而是融合模型将大量测试样本预测为一个或少数几个类别。

这一现象在医学图像中尤其严重，原因包括：

1. 医学任务通常有明确诊断类别，例如血细胞类型、器官类别、皮肤病类别或超声类别。
2. 多中心医学数据常伴随强 non-IID 和类别不平衡，不同客户端可能覆盖不同类别组合或不同患病率。
3. 常规模型融合主要处理参数空间冲突，不能保证每个诊断类别在融合后仍保留独立、稳定的决策方向。

为量化该现象，本工作新增了预测坍缩分析脚本：

```text
scripts/analyze_prediction_collapse.py
```

该脚本对已经生成的 merged checkpoint 做测试集前向推理，并统计预测分布。主要指标包括：

```text
pred_majority_ratio:
    测试集中被预测最多的类别所占比例。

pred_effective_classes:
    exp(H(predicted_label_distribution))，表示模型实际使用了多少个类别。

pred_entropy_norm:
    预测标签分布熵除以 log(C)，用于比较不同类别数任务上的预测分散程度。

pred_true_tv:
    预测标签分布与真实测试标签分布之间的总变差距离。
```

以 BloodMNIST 的 `resnet, clients=3, beta=0.01` 为例，测试集真实最大类占比为 `0.1947`。常规融合方法的最大预测类占比明显偏高：

| 方法 | Acc | 最大预测类占比 | 有效预测类别数 |
| --- | ---: | ---: | ---: |
| avg | 0.3069 | 0.6293 | 3.2309 |
| ties | 0.2797 | 0.5127 | 2.6195 |
| dare_linear | 0.3376 | 0.4385 | 3.9550 |
| dare_ties | 0.3315 | 0.3663 | 3.0097 |
| my_merge | 0.7989 | 0.1935 | 7.5115 |

该结果说明，常规融合方法在该格子上并非只是准确率较低，而是预测分布已经明显退化。`my_merge` 的预测最大类占比接近真实分布，同时有效预测类别数显著更高，说明其恢复了多类别医学诊断输出。

## 3. 方法概述

当前 `my_merge` 采用两个模块：

1. 诊断原型上传模块。
2. 原型头合成与患病率校准模块。

这两个模块均基于医学图像任务的类别结构。第一个模块解决常规融合中的诊断类别坍缩问题；第二个模块处理医学任务中真实存在的强类别比例偏斜。

对应实现位置如下：

```text
客户端统计:
    scripts/export_my_merge_prototypes.py

服务端融合:
    methods/my_merge.py

坍缩分析:
    scripts/analyze_prediction_collapse.py

结果汇总:
    My_merge_ret/汇总表.md
```

## 4. 模块一：客户端诊断原型上传

服务端与客户端共享一个 reference backbone。该 backbone 由公开实验配置构造，依赖数据集名称、模型结构、类别数、输入通道数、随机种子和是否使用预训练等信息。它不是任一客户端训练后的私有模型，也不由服务端读取客户端图像训练得到。

第 `i` 个客户端在本地拥有训练数据。对类别 `c`，客户端在本地统计两类信息：

```text
公式 (1): 类别样本数

count(i, c) = number of local samples whose label is c

公式 (2): 类别诊断原型

mean(i, c) =
    average reference-backbone feature
    over all local samples whose label is c
```

其中 `mean(i, c)` 是类别级均值，而不是逐样本特征。客户端上传的信息为：

```text
checkpoint
count(i, c)
mean(i, c)
```

服务端不会收到原始图像，也不会收到任意单张图像对应的 feature、logit 或预测结果。

这个模块的医学含义是：每个诊断类别在共享参考特征空间中都有一个形态中心。不同客户端的数据虽然 non-IID，但同一医学类别仍应在形态空间中形成可聚合的类别原型。相比直接平均分类头参数，该模块显式保留每个诊断类别的独立方向。

## 5. 模块二：服务端原型头合成与患病率校准

服务端收到各客户端上传的类别原型后，对每个类别单独聚合。客户端 `i` 对类别 `c` 的聚合证据定义为：

```text
公式 (3): 类别级客户端证据

e(i, c) = (count(i, c) + 1) ^ rho, if count(i, c) > 0
e(i, c) = 0, otherwise
```

当前实现中 `rho` 默认为 `0.45`。小于 1 的幂次使样本更多的客户端贡献更稳定，但避免大客户端完全支配某一类别。

类别级聚合权重为：

```text
公式 (4): 类别级归一化权重

alpha(i, c) = e(i, c) / sum_j e(j, c)
```

全局诊断原型为：

```text
公式 (5): 全局类别原型

prototype(c) = sum_i alpha(i, c) * mean(i, c)
```

服务端随后使用 reference backbone 构建原型分类头。当前默认使用 cosine prototype head：

```text
公式 (6): 原型分类头权重

weight(c) = scale * normalize(prototype(c))

公式 (7): 原型分类分数

score(c | x) = weight(c) dot feature(x) + bias(c)
```

其中 `scale` 默认为 `20.0`。

在强类别比例偏斜的医学任务中，单纯恢复多类别形态输出并不一定最优。例如 DermaMNIST 的测试集中最大类占比约为 `0.6688`。在这种情况下，类别比例本身包含真实的医学患病率先验。当前实现会根据客户端上传的类别计数估计全局类别先验，并在存在明显优势类别时加入 log-prior bias：

```text
公式 (8): 全局类别先验

prior(c) = total_count(c) / sum_k total_count(k)

公式 (9): 中心化 log-prior

centered_log_prior(c) =
    log(prior(c)) - average_k log(prior(k))

公式 (10): 校准后的 bias

bias(c) = strength * centered_log_prior(c)
```

该校准只在类别比例明显偏斜时启用。它的目标不是让模型盲目预测多数类，而是在形态原型分数之外补入医学任务中的患病率先验。

## 6. 隐私与通信边界

`my_merge` 的通信过程为：

```text
本地训练完成
-> 客户端本地统计类别级原型和类别计数
-> 一次性上传 checkpoint 与类别级统计
-> 服务端一次性生成 merged model
```

该过程不是联邦学习，因为它没有多轮模型下发、客户端继续训练、再上传更新的闭环。

服务端可见的信息包括：

```text
客户端 checkpoint
每个客户端每个类别的样本数
每个客户端每个类别的 reference-backbone feature 均值
```

服务端不可见的信息包括：

```text
客户端原始图像
逐样本 feature
逐样本 logit
逐样本预测
客户端本地训练过程中的 batch 级数据
```

因此，当前方法使用的是类别级聚合医学统计，而不是服务端直接访问客户端数据。该设定符合“客户端可以上传必要统计，但服务端不能看到原始数据”的约束。

## 8. 当前性能摘要

基于当前 `My_merge_ret/汇总表.md` 的统计，若不删除任何 baseline，`my_merge` 在全表中达到或超过当前最佳 baseline 的格子数为：

| 统计范围 | my_merge 达到或超过最佳 baseline |
| --- | ---: |
| 全部格子 | 195/300 |
| Raw | 145/225 |
| Client Average | 50/75 |

其中 Client Average 是当前更重要的观察对象，因为它消除了不同 beta 设置带来的部分波动。当前结果说明 `my_merge` 已经显著超过大量通用融合方法，但仍存在被部分强 baseline 或个别数据集格子阻塞的情况。

预测坍缩分析给出了更直接的方法证据：

1. 在相对均衡的 BloodMNIST 设置中，常规融合方法明显坍缩，`my_merge` 恢复了接近真实标签分布的多类别输出。
2. 在强偏斜的 DermaMNIST 设置中，单纯恢复均衡输出会损失准确率；加入患病率校准后，准确率可恢复到多数类先验较强的水平。

## 9. 当前结论

本工作目前形成了一个较清晰的方法链条：

1. 医学图像多中心模型融合的主要失败模式之一是预测坍缩。
2. 坍缩来自融合后诊断类别方向失配，因此只在权重空间做平均或符号投票不足以解决问题。
3. 客户端上传类别级诊断原型，可以在不暴露原始图像和逐样本信息的前提下，为服务端提供每个医学类别的形态锚点。
4. 服务端将这些类别原型写入分类头，可以显式恢复每个诊断类别的决策方向。
5. 对于类别比例高度偏斜的医学任务，类别先验本身具有诊断意义，因此需要受控的患病率校准。

该方法的论文表述应强调“医学诊断类别原型”和“患病率校准”两个核心概念，而不是候选池搜索、公开 probe 选择或数据集特判。

## 10. 仍需谨慎表述的问题

当前方法已经在汇总表中取得较好的整体表现，但有两个问题在论文写作中需要谨慎处理：

1. 患病率校准在 DermaMNIST 等强偏斜任务上可以提升准确率，但 hard prediction 仍可能高度集中到多数类。因此它应被表述为“利用医学患病率先验进行校准”，而不是简单声称“完全消除坍缩”。
2. 当前结果仍需进一步扩展预测分布分析，覆盖更多 backbone、客户端数量和 beta 设置，从而将代表性格子的现象证明扩展为全表统计证据。

后续实验应优先补充全量预测坍缩统计，而不是继续堆叠候选融合规则。只有当新增模块能解释明确医学现象，并在全表上稳定提升，才应进入正式方法。
