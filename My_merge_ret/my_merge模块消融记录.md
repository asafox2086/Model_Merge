# MyMerge 模块消融记录

本记录用于固定当前两模块设计的消融结论。实验只使用客户端上传的聚合统计，不使用服务端私有原图、公开 probe 或候选池选择。

## 模块定义

**M1：诊断原型重建。** 客户端在共享 reference backbone 上，为每个诊断类别上传类别样本数和类别特征均值。服务端聚合得到每类原型，并用归一化原型构造分类头。

**M2：患病率感知坍缩校正。** 服务端由客户端上传的类别样本数估计全局类别先验，在类别极度不平衡时向 M1 的 prototype classifier bias 加入 log-prior 校正。

## 消融设置

代表性 smoke 使用 `resnet`、`beta=0.01`、5 个医学小图数据集和 3/5/7 个客户端，共 15 个格子。

比较四种设置：

| 设置 | 含义 |
| --- | --- |
| `avg` | 普通权重平均 |
| `m1_only` | 只使用诊断原型重建，关闭 M2 prior bias |
| `avg_m2` | 普通权重平均后只加 M2 prior bias |
| `full` | M1 + M2 |

## 结果摘要

| 设置 | 15 格平均 Acc | 单格平均耗时 |
| --- | ---: | ---: |
| `avg` | 0.2912 | 11.69s |
| `m1_only` | 0.5744 | 11.81s |
| `avg_m2` | 0.2556 | 11.87s |
| `full` | 0.5956 | 11.75s |

`full` 与 `avg` 的耗时基本一致，额外开销主要是一次分类头重建和 bias 校正；端到端时间仍由测试集前向推理主导。

## 关键观察

M1 是主要收益来源。血液、超声、器官数据上，`m1_only` 已经显著超过 `avg`。例如 bloodmnist 从 0.19-0.36 提升到约 0.80，organcmnist 从 0.11-0.15 提升到约 0.61。

M2 不应作为独立融合方法。`avg_m2` 基本不能修复已经坍缩的平均模型，甚至会在 dermamnist c5 上明显降低性能。因此论文中不应把 M2 写成一个独立模型，而应写成接在 M1 后的患病率校正项。

M2 的作用是修复 M1 在极端类别先验下的过度均衡。dermamnist c7/beta0.01 从 `m1_only` 的 0.4369 提升到 `full` 的 0.6653，接近 `avg` 的 0.6688；这是 M2 的核心消融证据。

## 结论

正式方法保留两个模块：

1. M1 负责用医学诊断类别原型重建判别边界，是主要性能来源。
2. M2 只作为 M1 的类别先验校正，解决医学数据类别不平衡导致的 prototype head 过度均衡问题。

正式消融建议报告 `avg`、`M1 only` 和 `M1 + M2`。`Avg + M2` 可以放入补充材料，用于说明 M2 不是单独替代模型融合的组件，而是服务于 M1 的坍缩校正。
