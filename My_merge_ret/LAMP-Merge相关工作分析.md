# LAMP-Merge 相关工作分析

本文研究的是一种一次性异步医学模型融合问题：多个医疗机构在本地独立完成训练后，仅向服务器上传一次模型及类别级统计信息，服务器在不访问客户端原始医学图像、逐样本特征、逐样本 logit 或逐样本预测的条件下，合成一个统一的全局诊断模型。该设定同时涉及模型融合、医学模型融合和隐私协作学习，但又不同于其中任意一类已有问题。基础模型融合方法通常满足事后合并的形式要求，但缺乏医学诊断类别意识，容易在类别缺失和长尾分布下发生预测坍缩；医学模型融合方法能够利用医学数据结构，但往往依赖服务器端目标图像、验证反馈或患者级样本，难以满足本文的隐私边界；联邦学习和去中心化学习能够处理多方协作训练，但依赖多轮通信和客户端持续优化，不能直接用于训练完成后的单次异步合并。因此，LAMP-Merge 的出发点不是简单改造某一个已有融合算法，而是在这三类方法的共同缺口上重新定义医学模型融合变量：将类别无关的参数融合转化为客户端上传的类别级诊断证据融合。

## 基础模型融合：类别无关融合诱发医学预测坍缩

基础模型融合主要关注如何在不重新训练的情况下整合多个已经训练好的模型检查点。权重平均和 Model Soups 直接在参数空间中插值，Task Arithmetic 将模型表示为相对于共享初始化的参数增量并在增量空间中组合，Git Re-Basin 通过神经元置换对齐缓解不同模型间的排列不一致，TIES-Merging 和 DARE 系列方法通过裁剪小幅更新、符号投票或随机丢弃并重缩放任务向量来降低参数干扰，RegMean、Fisher merging、Model Stock、Breadcrumbs、Iso-C、FreeMerge 和 RobustMerge 等方法进一步引入几何结构、曲率估计或鲁棒统计假设。这些方法构成了事后模型融合的重要技术基础，也为本文提供了必要基线。然而，它们在医学多中心场景中的核心限制在于融合变量是类别无关的：算法处理的是全局参数、任务向量、曲率矩阵、置换结构或更新符号，而不是“哪个客户端在哪个诊断类别上具有可靠医学证据”。在多中心医学图像任务中，客户端数据常常同时具有局部类别缺失和长尾患病率分布；某个客户端可能对少数诊断类别具有较强判别能力，却完全没有见过其他类别。当类别无关的参数融合把这些局部模型直接平均、裁剪或投票时，可靠类别方向会与缺失类别方向和冲突方向混合，局部可控的类别偏置会被放大为全局预测分布坍缩。实验中的预测分布诊断也表明，许多通用融合基线在融合后会集中输出单一类别或少数主导类别，即使原始 accuracy 在某些长尾数据集上看似不低，其 balanced accuracy、macro F1 和 effective classes 仍显著退化。因此，基础模型融合在本文场景下的失效并非仅仅来自参数空间优化不足，而是来自融合对象与医学数据结构之间的不匹配。LAMP-Merge 对此的解决思路是将融合单位从全局参数更新改为类别级诊断证据：客户端本地计算每个诊断类别的参考特征原型和支持计数，服务器按类别重建全局诊断原型分类器，从而显式保留不同客户端在不同医学类别上的局部可靠性。

## 医学模型融合：医学结构有效但服务器端隐私边界不匹配

医学模型融合和医学多模态融合方法强调医学数据具有不同于通用视觉或自然语言任务的结构特征。例如，临床时间序列融合方法处理非规则采样的观察记录，图结构方法建模生理传感器之间的关系，图像-电子病历融合方法联合胸片、生命体征或临床记录；近期医学模型融合方法则进一步围绕医学图像迁移、医学模型选择、医学分割基础模型和医学模型鲁棒性进行设计。这些工作说明医学领域确实需要领域专用的融合变量，而不能仅依赖通用参数平均。然而，它们通常并不满足本文的服务器端隐私边界。许多医学融合方法在训练或选择阶段需要访问患者级样本、目标域图像、服务器端验证集、逐样本预测反馈或模型生成轨迹；FissionFusion 一类方法依赖验证性能进行分层 souping，MedMerge 一类方法需要目标域反馈来学习融合权重，MedSAMix 面向医学分割基础模型的层级优化而非多客户端分类器合并，InMerge 则主要在单个模型内部进行 kernel 合并而不是跨客户端 checkpoint 融合。若服务器集中使用目标图像或验证图像进行融合权重估计，便会越过本文设定的隐私边界；若将验证过程发回客户端完成，则会引入额外的交互反馈，使协议从一次性事后融合转向更接近联邦优化的通信模式。因此，现有医学融合方法虽然证明了医学结构的重要性，却不能直接作为本文的一次性异步医学模型融合方案。LAMP-Merge 保留医学结构建模这一原则，但将服务器可见信息限制为类别级聚合统计：服务器只接收 checkpoint、类别支持数、类别患病率计数和参考特征空间中的类别原型，不接收原始图像或逐样本输出。这样，方法既利用了医学诊断类别明确、患病率长尾和中心间类别覆盖不一致等领域特征，又避免了将患者级数据集中到服务器端。

## 联邦学习：多轮通信协议难以适配异步事后融合

联邦学习和去中心化学习是隐私敏感医学人工智能中的重要路线。FedAvg 及其变体通过“服务器下发全局模型、客户端本地训练、客户端上传更新、服务器聚合”的多轮过程学习全局模型；Swarm Learning 去除传统中心参数服务器，通过去中心化协调机制实现多方协作；Gossip Learning 以点对点方式异步传播模型，使参与者在多次局部训练和模型交换中逐步获得协作收益；FedSoup 等个性化联邦方法进一步维护模型池，并为不同客户端选择 local/global 插值模型。这些方法在客户端能够长期在线、接受多轮通信并持续参与训练时具有明确价值，也适用于需要个性化模型的医疗协作学习场景。但本文问题的通信约束更严格：各医院可能在不同时间完成训练，训练结束后只执行一次上传，服务器不再反复下发中间全局模型，客户端也不会根据服务器聚合结果继续优化。多轮联邦协议在真实医疗部署中还会受到机构协调、网络可用性、训练成本、审批流程和设备异构性的限制。因此，联邦学习解决的是协作训练问题，而本文解决的是训练完成后的异步事后融合问题。LAMP-Merge 不建立联邦式反馈闭环，也不要求客户端参与后续优化；它将通信过程压缩为一次本地统计上传和一次服务器端模型构造，在保留本地训练和服务器无原始图像访问的前提下，输出一个所有客户端共享的全局诊断模型。
