# LAMP-Merge 相关工作分析

本文的相关工作不宜写成现有论文的简单罗列，而应围绕本文问题设定进行分类讨论。核心逻辑是：现有方法分别解决了参数空间融合、联邦式协作训练、医学多模态融合或医学模型选择问题，但它们在“一次性异步医学模型融合、服务端不访问原始医学图像、输出单一全局诊断模型”这一联合设定下存在结构性缺口。

## 一、分类综述逻辑

| 方法类别 | 代表方法 | 方法假设 | 在本文场景下的限制 | LAMP-Merge 的对应设计 |
|---|---|---|---|---|
| 通用事后模型融合 | Weight Averaging, Model Soups, Task Arithmetic, Git Re-Basin, TIES-Merging, DARE, RegMean, Fisher, Model Stock, Breadcrumbs, Iso-C, FreeMerge, RobustMerge | 在权重、任务向量、置换空间、曲率或鲁棒统计空间中融合检查点 | 融合变量是类别无关的，不刻画客户端在哪些诊断类别上具有可靠证据；在医学长尾和局部类别缺失下容易诱发预测坍缩 | 将融合单位从全局参数更新改为类别级诊断证据，使用客户端上传的诊断原型与类别计数进行融合 |
| 联邦与去中心化医学学习 | FedAvg, Swarm Learning, Gossip Learning | 客户端可多轮接收全局模型、继续本地训练并重复上传更新 | 解决的是多轮协作训练，不是本地训练结束后的单次异步合并；通信和部署成本与本文设定不一致 | 只要求客户端完成一次上传，服务端一次性生成全局模型，无多轮反馈闭环 |
| 医学多模态与临床融合 | mTAN, Raindrop, MedFuse 等 | 训练阶段可访问患者级样本、时间戳、传感器序列、EHR 或多模态记录 | 融合的是输入模态或患者表征，不是独立训练后的图像分类器检查点；通常依赖患者级数据或服务器端验证反馈 | 保留医学结构建模思想，但只使用类别级统计，不要求服务端访问原始图像或逐样本输出 |
| 医学模型融合与医学模型选择 | FedSoup, MedMerge, FissionFusion, MedSAMix, InMerge | 依赖个性化联邦模型池、目标域数据、验证集选择、分割基础模型优化或单模型内部核融合 | 部分方法需要服务器端目标图像或验证反馈，部分方法需要多轮联邦过程，部分方法不输出一个统一全局分类器 | 面向同任务、多客户端、类别不完整的医学图像分类器，输出单一全局 checkpoint |

## 二、通用事后模型融合

通用事后模型融合旨在整合已经训练完成的模型检查点，从而避免联合训练或重新训练带来的成本。现有方法可以按照融合变量进行归类。第一类方法直接在权重空间中插值，例如权重平均和 Model Soups；当多个模型仍处在兼容的参数盆地中时，这类方法能够取得较好的融合效果。第二类方法在参数增量空间中运算，例如 Task Arithmetic 将微调模型表示为相对于共享初始化模型的参数位移，并对这些位移进行线性组合。第三类方法试图在平均前消除参数干扰，例如 Git Re-Basin 通过神经元置换对齐减少排列不一致，TIES-Merging 和 DARE 系列方法通过裁剪微小更新、符号投票或随机丢弃并重缩放任务向量来缓解更新冲突。第四类方法进一步引入几何、曲率或鲁棒统计假设，例如 Fisher 融合、RegMean、Model Stock、Breadcrumbs、Iso-C、FreeMerge 和 RobustMerge。

这些方法构成本文的重要基线，但其融合变量并未针对医学诊断类别建模。它们操作的是全局参数、任务向量、曲率估计、置换结构或更新符号，而不是“客户端 \(i\) 是否在诊断类别 \(c\) 上拥有可靠证据”。在多中心医学图像任务中，客户端训练集通常同时存在类别缺失和长尾分布；当许多客户端-类别对满足 \(n_{i,c}=0\) 时，类别无关的参数融合会把某个客户端中可靠的类别方向与其他客户端中缺失或冲突的方向混合。结果是融合模型可能保留多数类方向，同时抑制罕见类或局部缺失类，形成预测分布高度集中的全局坍缩模型。

因此，通用融合方法在本文场景下失效的关键并非其参数融合技术本身不充分，而是其融合变量与多中心医学数据的核心结构不匹配。医学图像融合需要显式表示类别级诊断可及性，即每个客户端对不同诊断类别的证据强度不同。LAMP-Merge 的 M1 正是针对这一缺口设计：它不直接平均分类头，而是由客户端上传类别原型和类别支持数，并在服务端按类别重建全局诊断原型分类器。

## 三、联邦与去中心化医学学习

联邦学习和去中心化学习是隐私敏感医学人工智能中的重要研究方向。FedAvg 及其变体通过多轮通信训练全局模型：服务器下发模型，客户端执行本地优化，随后上传更新并由服务器聚合。Swarm Learning 去除了传统中心参数服务器，利用去中心化协调机制实现多方训练。Gossip Learning 进一步以点对点方式异步传播模型，使参与者在局部训练和模型交换中逐步获得协作收益。

这些方法适用于客户端能够长期在线、反复通信并根据中间全局模型继续训练的场景。然而，本文研究的问题并不是协作训练，而是训练完成后的单次异步合并。现实医疗部署中，不同医院可能在不同时间完成训练，且难以承担反复下发、训练和回传的协议成本。因此，本文设定中服务器不会向客户端发送一系列全局模型，客户端也不会在观察服务器聚合结果后继续优化。

由此可见，联邦学习和去中心化学习解决的是多轮训练协议问题，而 LAMP-Merge 解决的是一次性事后融合问题。LAMP-Merge 只要求客户端在本地训练结束后上传一次模型和类别级统计；服务端在不建立多轮反馈闭环的情况下生成一个统一全局诊断模型。

## 四、医学多模态与临床融合

医学融合方法通常利用临床数据中特有的结构。例如，mTAN 使用连续时间注意力处理非规则采样时间序列，Raindrop 使用图结构建模生理传感器之间的关系，MedFuse 将胸片图像与临床时间序列进行融合。这些工作表明，医学数据不是通用融合算法的简单应用场景；医学数据具有非规则时间结构、模态异质性、临床测量机制以及疾病患病率分布等特征。

然而，这类医学融合方法通常融合的是患者级输入模态或临床表征，而不是独立训练后的医学图像分类器检查点。其训练过程往往需要访问患者级样本、时间戳、多模态记录、EHR 或服务器端验证反馈。当服务器不能查看客户端原始医学图像、逐样本特征、逐样本 logit 或逐样本预测时，这类方法不能直接用于本文的一次性模型融合设定。

LAMP-Merge 接受医学融合研究的基本原则，即融合方法必须利用医学结构，而不能只照搬通用领域算法。但 LAMP-Merge 将医学结构限定在可上传的类别级统计中：客户端本地计算诊断类别原型和患病率计数，服务端只基于这些聚合统计完成模型构造。因此，它既保留医学专用性，又避免了患者级数据在服务器端集中。

## 五、医学模型融合与医学模型选择

近期医学模型融合研究进一步说明，医学图像模型确实需要领域专用的融合变量，但这些方法仍与本文协议不同。FedSoup 属于个性化联邦学习框架，客户端在联邦训练过程中维护模型池，并为个体客户端选择 local/global 插值模型；它依赖联邦训练动态，不是一次上传后输出单一全局模型的事后融合方法。MedMerge 学习 kernel-level 融合权重，用于不同初始化模型向目标医学任务迁移；其目标是目标域迁移和融合权重学习，而不是在同一任务下合并类别覆盖不完整的多客户端检查点。FissionFusion 通过生成多个模型并使用验证性能进行分层 souping 完成医学模型选择；该流程依赖验证反馈和模型生成轨迹，不符合服务器无原始图像和无逐样本反馈的边界。MedSAMix 面向 SAM/MedSAM 这类医学分割基础模型，通过层级优化融合 generalist 和 specialist segmenter；其任务形式是医学分割，不是类别长尾的医学图像分类。InMerge 在单个模型微调过程中合并相似 kernel，本质上是单模型内部的鲁棒性正则化，而不是跨客户端 checkpoint 融合协议。

这些医学方法对本文的启示在于：医学模型融合需要使用医学结构，而不是只在参数空间做通用平均。但它们尚未覆盖本文的联合约束。若方法需要服务器端目标图像、验证图像或经验反馈来估计融合权重，则会触及服务器端数据边界；若把评估过程发回客户端执行，则会引入额外反馈通信，使协议接近联邦优化而非一次性事后融合；若方法只在单模型内部操作，则不能解决多客户端融合问题。

LAMP-Merge 面向这一缺失区域：客户端只上传训练后的 checkpoint、类别支持数、类别患病率计数和参考特征空间中的类别原型；服务端一次性构建共享诊断模型。该设计使融合变量与多中心医学图像中的类别依赖性诊断可及性和长尾患病率相一致。

## 六、可用于论文的归纳段落

综上，现有工作可以概括为三条主要路线。第一，通用事后模型融合方法满足单次合并的形式要求，但缺乏诊断类别意识；在多中心医学图像中，它们容易把局部类别偏置放大为全局预测坍缩。第二，联邦学习和去中心化医学学习能够处理隐私敏感协作训练，但依赖多轮通信和客户端持续优化，不能直接解释本地训练完成后的异步一次性合并。第三，医学多模态融合和医学模型选择方法体现了医学结构的重要性，但通常需要患者级样本、服务器端验证数据、目标域反馈或多轮模型池交互。

本文的问题恰好位于上述路线的交叉空白处：我们需要一个医学专用、一次性异步、服务端无原始图像访问、并输出单一全局诊断模型的方法。LAMP-Merge 的关键区别在于，它把融合变量从类别无关的参数更新转化为类别级诊断证据。M1 使用客户端上传的诊断原型重建全局多类别判别头，以抑制后置融合诱发的预测坍缩；M2 使用客户端上传的患病率计数进行有界长尾校准，以保留医学长尾分布中真实存在的多数类先验。由此，LAMP-Merge 同时满足本文的通信、隐私和医学专用性要求。
